1Mục tiêu

  • Tổ chức ứng dụng React thành nhiều Functional Component.
  • Dùng Hooks useState, useEffect để quản lý trạng thái và vòng đời.
  • Cài đặt đầy đủ mô hình CRUD trên dữ liệu lấy từ API jsonplaceholder.typicode.com/users.
  • Thực hành luồng dữ liệu một chiều và kỹ thuật State Lifting.
  • Thiết kế form thêm/sửa dạng modal, giao diện thân thiện, dùng được trên điện thoại.

2Cấu trúc ứng dụng

Toàn bộ ứng dụng nằm trong một file react-crud.html. React, ReactDOM và Babel được nạp qua CDN, mã JSX viết trong thẻ <script type="text/babel"> và render vào <div id="root">.

ComponentVai tròState / Props
AppComponent gốc, giữ state dùng chung và truyền xuống constate: kw, newUser
SearchFormÔ nhập từ khóa tìm kiếmprops: onChangeValue
AddUserNút “+ Thêm” và modal form thêm người dùngstate: adding, user

ResultTableTải dữ liệu, lọc, hiển thị bảng, sửa và xóastate: users, loading, editing

function App() {
  const [kw, setKeyword] = React.useState("");
  const [newUser, setNewUser] = React.useState(null);
  return (
    <div className="container">
      <h1>Quản lý người dùng</h1>
      <div className="toolbar">
        <SearchForm onChangeValue={setKeyword} />
        <AddUser onAdd={setNewUser} />
      </div>
      <ResultTable keyword={kw} user={newUser} onAdded={() => setNewUser(null)} />
    </div>
  );
}

3Luồng dữ liệu một chiều

Hai component anh em (SearchForm, AddUser) không truyền dữ liệu trực tiếp cho ResultTable. Dữ liệu được đẩy lên App qua hàm callback, rồi App truyền xuống ResultTable qua props.

SearchFormonChangeValue(text)
→
Appkw, newUser
→
ResultTablekeyword, user
AddUseronAdd(user)
→
AppsetNewUser
→
ResultTableuseEffect([user])
Sau khi ResultTable thêm người dùng mới vào danh sách, nó gọi onAdded() để App đặt lại newUser = null. Nhờ vậy, nếu thêm tiếp một người có dữ liệu giống hệt, useEffect vẫn chạy lại.

4Hiển thị & tìm kiếm (Read)

Tải dữ liệu một lần khi mount

useEffect với mảng phụ thuộc rỗng [] gọi API đúng một lần. Trong lúc chờ, bảng hiển thị “Đang tải dữ liệu...”. Nếu lỗi mạng, người dùng nhận được thông báo.

React.useEffect(() => {
  fetch("https://jsonplaceholder.typicode.com/users")
    .then((res) => res.json())
    .then((data) => { setUsers(data); setLoading(false); })
    .catch(() => { alert("Không tải được dữ liệu!"); setLoading(false); });
}, []);

Lọc theo từ khóa

SearchForm gọi onChangeValue mỗi lần gõ phím. ResultTable dùng Array.filter() để lọc theo name hoặc username, không phân biệt hoa thường. Danh sách gốc không bị thay đổi, chỉ danh sách hiển thị được tính lại.

const kw = keyword.toLowerCase();
const filteredUsers = users.filter(
  (u) => u.name.toLowerCase().includes(kw) ||
         u.username.toLowerCase().includes(kw)
);

5Thêm người dùng (Create)

  • Form là Controlled Component: mỗi input lấy value từ state và cập nhật qua onChange.
  • Các trường street, suite, city nằm trong đối tượng lồng address, nên phải dùng spread operator ở cả hai cấp để không mất dữ liệu cũ.
  • Bắt buộc nhập Name và Username (đã bỏ khoảng trắng thừa bằng trim()).
const handleChange = (e) => {
  const { id, value } = e.target;
  if (ADDRESS_FIELDS.includes(id)) {
    setUser({ ...user, address: { ...user.address, [id]: value } });
  } else {
    setUser({ ...user, [id]: value });
  }
};

Trong ResultTable, một useEffect theo dõi prop user để thêm người mới vào danh sách:

React.useEffect(() => {
  if (user) {
    setUsers((prev) => {
      // id mới = id lớn nhất + 1, không bị trùng sau khi đã xóa
      const newId = prev.length > 0 ? Math.max(...prev.map((u) => u.id)) + 1 : 1;
      return [...prev, { ...user, id: newId }];
    });
    onAdded();
  }
}, [user]);

6Sửa người dùng (Update)

Khi bấm Sửa, người dùng được sao chép sâu (deep copy) sang state editing. Nếu chỉ gán tham chiếu, việc gõ trong form sẽ sửa luôn đối tượng address gốc trong bảng, kể cả khi bấm Hủy.

function editUser(u) {
  setEditing({ ...u, address: { ...u.address } });
}

function saveUser() {
  if (editing.name.trim() === "" || editing.username.trim() === "") {
    alert("Vui lòng nhập Name và Username!");
    return;
  }
  setUsers((prev) => prev.map((u) => (u.id === editing.id ? editing : u)));
  setEditing(null);
}

Array.map() tạo mảng mới, chỉ thay đúng phần tử có cùng id, nên React nhận ra state đã thay đổi và render lại.

7Xóa người dùng (Delete)

Người dùng bị xóa ngay khi bấm Xóa. Array.filter() tạo mảng mới không chứa phần tử cần xóa, vì React không cho sửa trực tiếp state.

function removeUser(id) {
  setUsers((prev) => prev.filter((u) => u.id !== id));
}
Dạng cập nhật hàm setUsers((prev) => ...) luôn làm việc trên phiên bản users mới nhất, tránh lỗi khi nhiều lần cập nhật xảy ra liên tiếp.

8Giao diện & modal form

  • Form thêm và sửa hiển thị trong modal: lớp phủ .modal-overlay (position: fixed, nền mờ backdrop-filter: blur) và hộp .modal-content chia lưới 2 cột.
  • Bảng nằm trong khung overflow-x: auto, cuộn ngang được trên màn hình nhỏ. Hàng được tô màu khi rê chuột.
  • Có màu riêng cho từng hành động: Thêm (gradient tím), Sửa (vàng), Xóa (đỏ), Lưu/Hủy.
  • Responsive: dưới 520px, modal chuyển về 1 cột.
  • Hiển thị “Không có người dùng nào” khi kết quả tìm kiếm rỗng.

10Kiểm thử & kết luận

Kịch bản kiểm thử

  • Tải trang: hiển thị 10 người dùng từ API.
  • Tìm kiếm “le” lọc đúng theo name/username, không phân biệt hoa thường; xóa từ khóa thì hiện lại toàn bộ.
  • Thêm người dùng hợp lệ: xuất hiện cuối bảng với id mới. Bỏ trống Name/Username thì bị cảnh báo.
  • Xóa một người rồi thêm mới: id không bị trùng.
  • Sửa rồi bấm Hủy: dữ liệu trong bảng giữ nguyên (deep copy hoạt động đúng).
  • Sửa rồi bấm Lưu: chỉ đúng dòng đó được cập nhật, kể cả các trường địa chỉ.
  • Xóa: dòng biến mất ngay, các dòng khác không bị ảnh hưởng.
  • Giao diện trên điện thoại: bảng cuộn ngang, modal 1 cột.

Kết luận

Bài tập đã hoàn thành đầy đủ chức năng CRUD và tìm kiếm theo đúng mô hình luồng dữ liệu một chiều của React. Qua bài, em nắm được cách dùng useState, useEffect, kỹ thuật State Lifting, Controlled Components và nguyên tắc không sửa trực tiếp state (luôn tạo đối tượng/mảng mới bằng spread, map, filter).

Hạn chế: dữ liệu chỉ lưu trong bộ nhớ trình duyệt, tải lại trang sẽ mất các thay đổi, vì JSONPlaceholder không lưu thật. Hướng phát triển: lưu vào localStorage hoặc gọi API POST/PUT/DELETE tới một backend thật.
